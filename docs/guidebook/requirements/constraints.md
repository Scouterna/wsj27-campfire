# Constraints

These are the fixed boundaries Campfire is built inside. Each technical one is a decision already made and written down, so the table names the constraint and links the reasoning rather than re-arguing it. What Campfire is held to inside these boundaries is on [Quality attributes](./quality).

| Constraint                   | What it means                                                                                                                                                                  | Decision                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| One web application          | Every screen is built once, in the web application. The Android and Apple shells are thin by rule, and own only what a webview cannot reach.                                   | [ADR 010](/decisions/010-deliver-the-front-end-as-one-web-application-in-native-shells)     |
| One origin                   | The application and every back-end answer on the same origin, each back-end under its own prefix, so the web application never learns which environment it is running in.      | [ADR 012](/decisions/012-run-campfire-in-three-environments-on-one-origin)                  |
| A versioned bridge           | The web application and a shell talk through versioned messages rather than calls into each other, because a shell already on a phone cannot update in step with a web deploy. | [ADR 018](/decisions/018-bridge-the-web-application-and-the-shells-with-versioned-messages) |
| Offline-first reads          | A screen draws what the cache holds and asks for a fresh answer behind it, and the cache survives a restart. Connectivity on the island is a hope, not an assumption.          | [ADR 017](/decisions/017-route-and-load-data-with-tanstack-router-and-query)                |
| Borrowed identity            | Sign-in goes through ScoutID, and the session lives in httpOnly cookies on the application's own origin that the web application never reads.                                  | [ADR 019](/decisions/019-authenticate-on-the-app-origin-through-scoutid)                    |
| The back-end lives elsewhere | The services are in repositories of their own, with their own languages and release cadence. This repository can ask for an endpoint but not add one.                          | [ADR 013](/decisions/013-keep-the-back-end-services-in-their-own-repositories)              |
| One monorepo                 | The web application, the shells, the modules, the libraries, the tooling, and the documentation are one repository, versioned together.                                        | [ADR 002](/decisions/002-organize-as-a-single-monorepo)                                     |
| TypeScript and pnpm          | One language across the front-end and the tooling, ES modules only, with the Node.js version pinned.                                                                           | [ADR 004](/decisions/004-build-on-pnpm-and-typescript)                                      |
| Pinned, aged dependencies    | Versions are exact, and a release less than three days old does not install, so adding a dependency is a deliberate act.                                                       | [ADR 005](/decisions/005-pin-every-dependency-and-let-new-releases-age)                     |
| Warnings are failures        | One strict tool per language settles formatting and correctness, across TypeScript, Kotlin, and Swift, and a warning fails the check.                                          | [ADR 006](/decisions/006-lint-and-format-with-a-shared-strict-toolchain)                    |
| Swedish only                 | Every word a user reads is Swedish, with no translation layer and no locale switch, because everyone it is for reads Swedish.                                                  | [ADR 011](/decisions/011-write-every-word-a-user-reads-in-swedish)                          |

Three more constraints come from the shape of the work rather than the technology:

- **The team is small.** Every choice has to be one a small team can carry through the build and the camp. That is why there is one web application instead of two native ones, why the tooling is strict enough to settle style without a reviewer, and why an approach that needs a platform team loses.
- **The date does not move.** The jamboree runs 30 July – 8 August 2027, and the contingent is traveling from late July until the last people are home on 10 August. A feature that is not ready by then has missed the event it existed for.
- **During camp, the only fix that ships fast is a web deploy.** For three weeks the people who need Campfire and the people who can fix it are on the same trip, and a store review in the middle of that is not a recovery plan. This is why [Quality attributes](./quality) puts deployability first.

The web-first shape has a known cost. Apple's minimum-functionality guideline is a review risk for an app built on a webview, so the shells carry real native behavior – the navigation and tab bars, and the sign-in flow in a modal – rather than wrapping a page and stopping ([ADR 010](/decisions/010-deliver-the-front-end-as-one-web-application-in-native-shells)).
