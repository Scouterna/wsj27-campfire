# Glossary

The shared vocabulary used across this guidebook, the decisions, and the code, so everyone reads them with the same terms. Swedish words are kept where the contingent uses them – a leader looking for "avdelning" should find it. Where a term has a chapter or a decision behind it, the entry points there.

## The jamboree

| Term             | Meaning                                                                                                                                                   |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WSJ27            | The 26th World Scout Jamboree, 30 July – 8 August 2027 on Wyspa Sobieszewska outside Gdansk, Poland. The 27 is the year, not the ordinal.                 |
| Bravely          | The jamboree's theme. Bravely Script, the display typeface in the app, takes its name from it.                                                            |
| WOSM             | The World Organization of the Scout Movement, which owns the World Scout Jamboree.                                                                        |
| ZHP              | Związek Harcerstwa Polskiego, the Polish Scouting and Guiding Association, hosting WSJ27 with WOSM.                                                       |
| Scouterna        | The Swedish Scout and Guide Association, which organizes Sweden's contingent and owns Campfire.                                                           |
| Contingent       | A national delegation to the jamboree. Sweden's is roughly 2,600 people in 53 units – the largest it has ever sent.                                       |
| Unit (avdelning) | The contingent's basic group: 36 scouts and 4 leaders. The register's unit number is a person's home in the contingent, and its API calls a unit a troop. |
| Patrol           | Nine scouts and an adult patrol leader; four patrols make a unit. IST are organized in patrols rather than units.                                         |
| Subcamp          | One of the jamboree's 16 participant subcamps, around 2,250 people each. A unit camps in one of them.                                                     |
| Rundresa         | The round trip: a tour through Latvia and Lithuania before camp, leaving Sweden 21–22 July 2027.                                                          |
| Direktresa       | Direct travel: straight to Gdansk, leaving Sweden 26–27 July 2027.                                                                                        |
| Egen resa        | Own travel, offered to IST who book and pay for their journey themselves.                                                                                 |
| Förträff         | A pre-camp meeting where a unit gets to know each other and prepares together.                                                                            |
| Discord          | Where the contingent's day-to-day communication happens. Campfire deliberately does not integrate with it – see [Scope](../requirements/scope).           |

## The people

| Term                 | Meaning                                                                                                                                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Deltagare            | A participant – a scout aged 14 to 17 at the opening ceremony. In the register, never in front of the app.                                                                                                         |
| Ledare               | A unit leader, and the audience Campfire is shaped around first. See [Leaders](../context/people/leaders).                                                                                                         |
| IST                  | International Service Team – the adult volunteers, 18 and over, who staff the camp.                                                                                                                                |
| CMT (lagerledningen) | The contingent management team, and Campfire's other audience: Administration, Communication, Program, Head of Contingent, and Support. See [Context](../context/).                                                |
| Support              | The CMT function with three parts, each an audience of its own – [Health](../context/people/cmt-health), [IST support](../context/people/cmt-ist-support), and [Unit support](../context/people/cmt-unit-support). |
| HOC                  | Head of Contingent. Three of them lead the contingent and answer for it.                                                                                                                                           |
| Audience             | One of the nine people the architecture model draws, listed word for word in `.github/ISSUE_TEMPLATE/feature.yml` so an issue and a diagram name the same group.                                                   |
| Role                 | What the register says a person is, flattened into a colon-separated string the session carries – `wsj27:al:<unit>` for a leader, `wsj27:cmt:<funktion>:<roll>` for the management.                                |
| Health grant         | The grant that lets a caller read the register's health answers – the Support function's health role, or a per-person grant given in Scoutnet. Everyone else is refused outright.                                  |

## The product

| Term                     | Meaning                                                                                                                                                                                                                                                                                                                           |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Campfire                 | This product – the Swedish contingent's digital companion for WSJ27, for the leaders and the contingent management team.                                                                                                                                                                                                          |
| The web application      | `apps/web` – React and TypeScript, built with Vite, holding every screen and installable from the browser as a PWA ([ADR 014](/decisions/014-build-the-web-application-on-react-with-vite)). Its dev server runs on port 3000.                                                                                                    |
| Shell                    | A thin native app – Kotlin and Compose on Android, Swift and SwiftUI on Apple – that hosts the web application in a webview and owns only what the web cannot reach ([ADR 010](/decisions/010-deliver-the-front-end-as-one-web-application-in-native-shells)). Both ship as `se.scouterna.campfire`.                              |
| Tier                     | Which of the two the application is running in, browser or shell, decided once at boot from the shell's `CampfireShell` User-Agent token.                                                                                                                                                                                         |
| Bridge                   | The versioned JSON message contract between the web application and a shell – screen, session, and theme out; navigation and actions back ([ADR 018](/decisions/018-bridge-the-web-application-and-the-shells-with-versioned-messages)).                                                                                          |
| Module                   | A feature module under `modules/` – one domain capability, which never imports another module ([ADR 016](/decisions/016-compose-the-web-application-from-feature-modules)). There are four: authentication, home, journey, and participants. See [Modules](../architecture/modules).                                              |
| Library                  | A generic package under `libraries/` – `host`, `ui`, and `utils`. A library that knows a feature is a feature module in the wrong place. `utils` holds the small pure helpers – `stringOrFallback` and the `fetch` wrapper the data layer is built around – and the bar for adding one is that a second package already wants it. |
| Composition root         | `apps/web/src/main.tsx`, the one place that knows every module and assembles them into an application.                                                                                                                                                                                                                            |
| Widget                   | A piece of UI a module registers under an id, which the application places by that id, so one module's screen can show another module's content without importing it.                                                                                                                                                             |
| Address                  | A route path, branded with the module that owns it, so two modules claiming the same path is a compile error rather than a surprise at runtime.                                                                                                                                                                                   |
| Section                  | A top-level destination in the menu. In a shell, sections are the native tabs, and the web decides what they are.                                                                                                                                                                                                                 |
| Theme                    | One of the contingent's five color identities – blue, brown, green, red, and yellow – applied by name. What crosses the bridge is the name, never a color. See [Design](../design/).                                                                                                                                              |
| The register             | The contingent's list of people, with their units, roles, travel, contact details, and health answers. Every answer is scoped by who is asking.                                                                                                                                                                                   |
| Information level        | How much of a register answer comes back – name, basic, or full. Full carries the health answers and needs a health grant.                                                                                                                                                                                                        |
| Environment              | One of local, dev, and prod – defined by what sits behind the back-end paths, all three on the same origin ([ADR 012](/decisions/012-run-campfire-in-three-environments-on-one-origin)). See [The environments](../development/environments).                                                                                     |
| The one origin           | The single address everything answers on – `http://localhost:8000` while developing, `campfire.wsj27.se` in production. The application only ever fetches origin-relative paths.                                                                                                                                                  |
| ScoutID                  | Scouterna's identity provider, built on Keycloak, and how a person signs into Campfire. See [ScoutID](../context/systems/scoutid).                                                                                                                                                                                                |
| Scoutnet                 | Scouterna's member registry, and the source the register is derived from. See [Scoutnet](../context/systems/scoutnet).                                                                                                                                                                                                            |
| The auth service         | `wsj27-auth-api` – the Python service in its own repository serving `/api/auth` on the app's origin ([ADR 019](/decisions/019-authenticate-on-the-app-origin-through-scoutid)). See [Auth service](../context/systems/auth-service).                                                                                              |
| The participants service | `wsj27-project-api` – the Python service behind `/api/project`, serving the register derived from Scoutnet ([ADR 012](/decisions/012-run-campfire-in-three-environments-on-one-origin)). See [Participants service](../context/systems/participants-service).                                                                     |
| The mock                 | `tools/mock` – a stand-in for the whole back-end on port 8003, so local work and tests touch no network ([ADR 021](/decisions/021-stand-in-for-the-back-end-with-a-seeded-mock)). See [The mock back-end](../testing/mock).                                                                                                       |
| Persona                  | One of the mock's twelve seeded identities. Signing in locally is picking a name from the ScoutID stand-in's list, with no password.                                                                                                                                                                                              |

## The code

| Term             | Meaning                                                                                                                                                                                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Screen           | A whole destination a module exports, named `NameScreen.tsx`, with its stories beside it. See [Presentation layer](../architecture/layers/presentation).                                                                                                                                                |
| Domain model     | What a module knows a thing to be, independent of the shape the service sent. See [Domain layer](../architecture/layers/domain).                                                                                                                                                                        |
| The boundary     | Where an untyped payload becomes a domain model. Every field arrives `unknown` and is validated; a bad row is dropped rather than trusted. See [Data layer](../architecture/layers/data).                                                                                                               |
| Role translation | The seam that turns the flattened roles a ScoutID token carries into the closed set the application knows – a leader with their unit, the management and its functions, the health grant. One table, and an unknown spelling grants nothing; it is replaced whole when what the provider reports moves. |
| Public surface   | A package's `src/index.ts`, and nothing else in it. A module exports the screens and widgets the application mounts; a library exports what any module may reach for.                                                                                                                                   |
| Workspace root   | One of the four places pnpm looks for packages: `apps/*`, `libraries/*`, `modules/*`, and `tools/*`. Every package is named `@scouterna/wsj27-campfire-<name>`.                                                                                                                                         |

## Documenting the system

| Term               | Meaning                                                                                                                                                                                                                                                         |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Software guidebook | This site – a living description of Campfire as its first version is built, rewritten when the design changes rather than narrating how it got there ([ADR 028](/decisions/028-keep-a-software-guidebook)). It runs on port 3001 and publishes to GitHub Pages. |
| ADR                | Architecture Decision Record – a numbered, never-rewritten record of a decision and the alternatives it ruled out, under [Decisions](/decisions/).                                                                                                              |
| C4 model           | The notation the architecture diagrams use. One model under `docs/architecture/`, viewed at system context and container level plus a deployment view per environment ([ADR 030](/decisions/030-model-the-architecture-as-c4-in-structurizr)).                  |
| Container          | A C4 level, and here a real package taken from the repository – the web application, a shell, a module, a library – never an invented grouping.                                                                                                                 |
| Structurizr        | The tool the model is written for. `pnpm start:arch` serves its browser UI on port 3003 from `scripts/structurizr`, which is the only thing that writes a view's layout into `workspace.json`.                                                                  |

## Tooling and process

| Term                 | Meaning                                                                                                                                                                                                                                                   |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The four checks      | Formatting, lint, Markdown, and types – run as separate commands so one pass reports every failure. Warnings are failures. See [The checks](../development/checks).                                                                                       |
| Vitest               | The TypeScript test runner, with one project per package that has tests ([ADR 022](/decisions/022-test-typescript-with-vitest)). See [Unit tests](../testing/unit).                                                                                       |
| The walks            | The Playwright walk-throughs in `modules/*/test-ui`, one project per module, run against a dev server by `pnpm test:web:ui`. See [UI tests](../testing/ui).                                                                                               |
| Storybook            | The catalog of every component, widget, and screen, run on port 3002 and themed like this guidebook ([ADR 023](/decisions/023-catalog-the-ui-in-storybook)).                                                                                              |
| Prettier             | The formatter, configured in `config/prettier/`. It covers the Android shell's XML too, so one tool decides what formatted means across the repository.                                                                                                   |
| Caddy                | The web server in front of every environment, and inside the deployable image – the thing that makes one origin out of several services.                                                                                                                  |
| XcodeGen             | The generator that rebuilds `Campfire.xcodeproj` from `project.yml`, so the Xcode project is an output rather than a file people merge ([ADR 020](/decisions/020-generate-the-xcode-project-with-xcodegen)).                                              |
| CalVer               | The version scheme, `YEAR.FEATURE.PATCH`, as in `2026.1.0` ([ADR 007](/decisions/007-version-with-calver-on-a-rebased-history)). See [Release](../maintenance/release).                                                                                   |
| Conventional Commits | The commit message format – `<type>: <description>`, eleven types, no scope – enforced by a hook, and what decides which CalVer segment moves.                                                                                                            |
| GitHub Actions       | Where the same checks run on a pull request, as small workflows that each report their own status ([ADR 009](/decisions/009-check-and-release-with-small-github-actions-workflows)). See [Continuous integration](../development/continuous-integration). |
| Agent                | A written role definition – analyst, architect, developer, or reviewer – that does the work between human decisions. See [Process](../process/).                                                                                                          |
| Skill                | Reusable domain knowledge an agent reads, versioned in its frontmatter, where bumping the version is what publishes it ([ADR 025](/decisions/025-publish-agent-skills-as-versioned-releases)).                                                            |
| Spec folder          | `.agents/specs/<branch>/` – the requirements, design, and plan for a piece of work. Working scratch, never committed; the issue and the code are the record.                                                                                              |
